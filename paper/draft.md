# AI Model Attribution — Technical Report (Draft)

## 1. Problem Statement

Large language models can now produce text that is difficult to distinguish from human writing, raising two related but distinct forensic questions. First: was a given passage written by a human or by an AI system (binary detection)? Second, and less studied: if the text was AI-generated, which model family produced it (attribution)? This project builds a from-scratch system to answer both questions for English text in the 100-1000 word range, using a fixed, small set of model families chosen at the outset rather than attempting open-ended detection of any possible model.

The system is deliberately scoped. It does not claim near-certain (90%+) confidence for every model - current research does not support that claim, and the project's own results (Section 4) show real, honest limitations rather than an inflated headline number. It is not a production system or browser extension; it is a research and training exercise. It does not attempt version-level detection (e.g. distinguishing GPT-4 from GPT-4o) or prompt-archetype inference, both of which are left as future work. All models used in this pipeline - the tokenizer, the feature extractors, and the classifiers - are trained from scratch on labeled text; no pretrained language model or external AI API is called as part of the classification itself.

## 2. Related Work

Several existing benchmarks motivate and contextualize this work. MGTBench evaluates AI-generated text detection across multiple genres, with generations drawn from six major LLMs including ChatGPT-turbo, ChatGLM, Dolly, GPT4All, StableLM, and Claude. M4 extends this to a multi-generator, multi-domain, multi-source setting, covering GPT-4, ChatGPT, GPT-3.5, Cohere, Dolly-v2, and BLOOMz-176B across domains such as Wikipedia, Reddit, WikiHow, PeerRead, and arXiv abstracts. MULTITuDE contributes a large-scale corpus of AI-generated and human-written news articles for multilingual detection research. RAID (Robust AI Detection) is a widely used adversarial benchmark that stress-tests detectors against paraphrasing and other evasion techniques, and is commonly cited alongside MGTBench and M4 as a standard for detector robustness. HC3 (Human ChatGPT Comparison Corpus) is another widely used resource pairing human answers with ChatGPT-generated answers to the same questions, used extensively in early human-vs-AI detection work.

This project's dataset and baseline numbers come from a more recent, closely related resource: the Defactify Text Dataset (Rajarshi-Roy-research/Defactify_Text_Dataset), which pairs authentic New York Times articles with synthetic versions generated by six LLMs (Gemma-2-9B, Mistral-7B, Qwen-2-72B, Llama-8B, Yi-Large, and GPT-4o). Its authors report baseline results of 53% accuracy on binary human-vs-AI detection and 5.04% accuracy on attributing AI text to its generating model - a deliberately weak baseline intended to be improved upon by future work, which is exactly the role it plays in this project's Results section (Section 4).

## 3. Method

**Data.** This project uses the Defactify Text Dataset in full, taking its native train/validation/test splits (51,247 / 10,983 / 10,963 examples) rather than re-splitting, since those splits are already fixed and reproducible. The dataset provides two label columns: a binary human-vs-AI label (Label_A) and a seven-way label naming the specific source, human or one of six AI models (Label_B). For the attribution task, four of the six AI model classes were selected: GPT-4o, Llama-8B, Mistral-7B, and Qwen-2-72B, chosen to give a mix of a well-known closed-weight model (GPT-4o) against three prominent open-weight families.

**Binary detection.** A logistic regression classifier was trained on stylometric features only: sentence-length mean and standard deviation, punctuation ratios (comma, period, semicolon, exclamation, question), a hedge-word rate (frequency of words like "maybe", "perhaps", "likely"), and type-token ratio (lexical diversity).

**Attribution features.** For the harder four-class attribution task, the feature set was extended with part-of-speech distribution (nine tags, extracted via spaCy's en_core_web_sm model), discourse marker rate (frequency of connectives such as "however", "furthermore", "therefore"), and a per-model-class bigram language model perplexity score - one small n-gram model trained on each class's own training text, used to score how well a given passage "sounds like" each class.

**Feature ablation.** An ablation study (Section 6, Step 6) on a balanced sample found that including raw, unscaled perplexity scores actually hurt classification accuracy (35.4% vs. 44.7% without it), because the feature's scale (near-zero for well-matched text, capped at 1,000,000 as a fallback for unscorable text) dominated the other, ratio-based features. This was resolved for the final model by log-scaling the perplexity feature before combining it with the rest.

**Model selection.** Three attribution models were compared, in order: (1) logistic regression on unscaled features, which failed to clear the project's 40% macro-F1 floor (37% obtained); (2) the same model with StandardScaler applied to all features, which cleared both the target and floor (test accuracy 53.68%, macro F1 50.01%); (3) a LightGBM gradient-boosted tree classifier on the same scaled features, which produced a substantially stronger result (test accuracy 60.79%, macro F1 59.23%); and (4) the same LightGBM model with the log-scaled perplexity feature added, the final adopted model (test accuracy 61.00%, macro F1 59.48%). Per the project's own stopping rule (no more than two tuning attempts before locking in a result), tuning was stopped after the LightGBM-plus-perplexity attempt regardless of the modest size of its improvement over LightGBM alone.

## 4. Results

**Binary detection (human vs. AI).** The logistic regression detector achieved 91.26% accuracy and 95.04% F1 on the validation set, and 88.23% accuracy and 93.18% F1 on the held-out test set. This clears the project's 90% target on validation and clears the 80% floor comfortably on test. Against the Defactify baseline of 53% binary accuracy, this represents a very large improvement, though it should be noted the baseline paper's own detection setup may differ in specifics from this project's.

**Attribution (4-class: GPT-4o, Llama-8B, Mistral-7B, Qwen-2-72B).** The final model (LightGBM with log-scaled perplexity) achieved 73.99% accuracy and 73.94% macro F1 on validation, and 61.00% accuracy and 59.48% macro F1 on the held-out test set. Both figures clear the project's 55% target (on validation) and 40% floor (on test) with substantial margin. Against the Defactify baseline of 5.04% attribution accuracy, this is more than a tenfold improvement, though again the class sets are not identical (this project uses four of the six available AI classes, chosen deliberately rather than matching the baseline's exact setup).

The test-set confusion matrix for the final model shows uneven performance across classes: GPT-4o was correctly identified in 92% of cases, Mistral-7B in 69%, Llama-8B in 47%, and Qwen-2-72B in only 35% - the weakest class, most often confused with Mistral-7B. This asymmetry persisted, though it narrowed, across all three model iterations (18% correct for Qwen-2-72B under plain logistic regression, rising to 35% under the final LightGBM-plus-perplexity model), suggesting a genuine, if partially addressable, stylistic overlap between these two open-weight model families rather than a simple modeling artifact.

**Calibration.** Applying Platt scaling (5-fold cross-validated sigmoid calibration) to the attribution model produced a mean maximum predicted confidence of 47.18% on the test set, closely tracking the model's actual post-calibration accuracy of 48.84% - indicating the model's confidence scores are reasonably well-calibrated rather than overconfident, even though the underlying classification task remains difficult.

**Robustness.** Testing the final attribution model against a sample of 500 test passages subjected to light paraphrasing (random synonym substitution and occasional adjacent-sentence reordering) produced only a 0.2 percentage-point drop in both accuracy (55.20% to 55.00%) and macro F1 (51.18% to 51.01%). This indicates the model is robust to superficial lexical perturbation, though this finding should not be over-read: the paraphrasing method used was deliberately lightweight, and the model's robustness against more aggressive paraphrasing (e.g. full sentence restructuring by another language model) remains untested.

## 5. Limitations

- Qwen-2-72B remains the hardest class to attribute correctly even in the best model (35% recall), and is most frequently confused with Mistral-7B; this may reflect genuine stylistic similarity between these two model families rather than a fixable weakness in the feature set.
- The robustness evaluation used only light, rule-based paraphrasing (synonym swaps and occasional sentence reordering) on a 500-example sample. It does not test robustness against more sophisticated adversarial paraphrasing, such as another LLM rewriting the text.
- The Step 6 feature ablation study was run on a balanced sample (300 examples per class for training, roughly 100 per class for validation), not the full dataset, for speed; a full-data ablation might rank features somewhat differently.
- Only 4 of the 6 available AI model classes in the Defactify dataset were used for the primary attribution task (the 6-model stretch task, Section 5 Step 9, was not attempted, as the 4-class result already met all target metrics).
- All comparisons to the Defactify paper's published baseline (53% binary accuracy, 5.04% attribution accuracy) should be read with the caveat that this project's class selection (4 of 6 AI classes) and modeling approach differ from the original baseline paper's exact setup.
